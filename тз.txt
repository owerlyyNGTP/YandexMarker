1. Техническое задание на разработку сервиса «Яндекс.Метка» (YandexMarker)
1.1. Наименование продукта
«Яндекс.Метка» (YandexMarker) — сервис для создания и публикации пользовательских интерактивных карт на базе Яндекс.Карт.

1.2. Цель разработки
Создать веб-приложение и вспомогательного Telegram-бота, позволяющие пользователям:

Регистрироваться и авторизовываться.

Ставить персональные метки (места) на карту с названием, описанием и фотографией.

Загружать GPX-файлы (треки) для отображения маршрутов на карте.

Просматривать свои и публичные метки других пользователей.

Получать информацию о текущей погоде в выбранной точке через API Яндекс.Погоды.

Управлять метками через веб-интерфейс и команды бота в Telegram.

1.3. Функциональные требования
Веб-приложение (Flask):

Аутентификация: Регистрация, вход/выход (Flask-Login).

Карта: Интерактивная карта на всю страницу (API Яндекс.Карт).

Добавление меток: Клик по карте открывает форму с полями для названия, описания и загрузки изображения. Координаты подставляются автоматически.

Просмотр меток: Таблицы со списком меток пользователя и всех публичных меток.

Работа с файлами: Загрузка изображений для меток, загрузка GPX-файлов для отрисовки маршрутов.

REST API:

GET /api/markers — получение списка всех публичных меток в формате GeoJSON для отображения на карте.

GET /api/weather?lat=<широта>&lon=<долгота> — получение данных о погоде от API Яндекс.Погоды в формате JSON.

Администрирование: Панель администратора для просмотра пользователей и меток (доступна только пользователям с флагом is_admin).

Telegram-бот:

Регистрация: Команда /start приветствует пользователя и создает его учетную запись в БД.

Добавление меток: Команда /add <широта> <долгота> <название> добавляет новую метку.

Просмотр меток: Команда /list показывает список всех меток пользователя.

Погода: Команда /weather <широта> <долгота> возвращает сводку погоды от API Яндекс.Погоды.

Загрузка фото: Команда /photo переводит бота в режим ожидания изображения, которое будет прикреплено к последней добавленной пользователем метке.

Контекст: Бот сохраняет состояние пользователя (например, ожидание фото) для обработки последовательных действий.

1.4. Нефункциональные требования
ORM: Модели данных реализованы с помощью SQLAlchemy.

База данных: SQLite для простоты развертывания (с возможностью легкой замены на PostgreSQL).

Frontend: Адаптивный интерфейс на Bootstrap 5.

Загрузка файлов: Изображения и GPX-файлы сохраняются в директорию uploads/.

Код: Общий объем кода веб-приложения и бота должен превышать 700 строк.

Зависимости: Полный список зависимостей зафиксирован в файле requirements.txt.
